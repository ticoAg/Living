# 背景

Living 的用户是站长和被邀请的朋友；访客不用登录就能浏览公开内容。需求：

- 能在 Workers 上运行，不依赖额外服务。
- 站长能控制谁可以注册。
- 部署完成到站长注册之间，站点已经可以公开访问，这段时间不能被抢注。
- 不想配置邮件服务。

# 决定

1. **用户名加密码**：用户名 3–24 位，不区分大小写唯一；密码至少 8 位，用 WebCrypto 的 PBKDF2-SHA256 存储：10 万次迭代、16 字节盐、32 字节输出，存为 `pbkdf2$100000$<salt>$<hash>`（盐和哈希为 base64）。10 万次是 Workers 的 WebCrypto 对 PBKDF2 接受的最大迭代数。哈希串自带算法和迭代次数，以后升级可以在登录成功时重新哈希。
2. **会话放 KV**：登录成功生成 32 字节随机令牌，写入 `sess:<token>`（TTL 30 天），令牌放进 Cookie `living_session`（HttpOnly、Secure、SameSite=Lax）。令牌是不透明的随机串，不是 JWT；退出登录就是删除该键。见 [KV](/data/kv.md)。
3. **CSRF 与暴力破解**：写请求校验 `Origin` 与站点同源；登录按"IP 加用户名"限流，每分钟 5 次，成功后清零。用户名不存在时也做一次哈希校验，使耗时与密码错误一致。见 [接口约定](/api/conventions.md) 和 [认证接口](/api/auth.md)。
4. **邀请制注册**：`settings.registration` 为 `invite`（默认）、`open`、`closed`；邀请码存 [invites](/data/invites.md)，由站长和管理员生成。
5. **站长引导邀请码**：部署后数据库里没有用户，`GET /api/site` 返回 `needsSetup: true`。部署者用 wrangler 直接写入一条 `role = 'owner'` 的一次性邀请码；此时只有 owner 邀请码能注册，注册者成为站长。步骤见 [密钥与初始化](/runbooks/secrets.md)。

# 后果

- 没有外部依赖：不需要邮件服务、OAuth 应用或额外的密钥管理。
- 抢注窗口关闭：写库需要 Cloudflare 账号权限，邀请码就是所有权证明；用后即失效，没有常驻的管理员口令。
- 不能自助找回密码，因为没有邮箱。忘记密码时需要站长直接改库，或用新邀请码另注册账号。以后可以加管理员重置密码或 Passkey。
- 改密码不会让其他会话下线；退出登录后，别处的边缘节点最长约 60 秒内仍可能读到旧会话（KV 最终一致）。
- 带会话的接口请求每次读一次 KV，免费版每天 10 万次读，足够个人站点。
- PBKDF2 的 10 万次迭代让每次登录和注册消耗可观的 CPU 时间。免费版 Worker 每次调用 CPU 限制为 10 ms，若线上出现 `Worker exceeded resource limits`（Error 1102），需要升级到 Workers Paid（默认 30 秒 CPU 时间）。
- 限流计数在 KV 上，不是严格精确，但足以挡住在线暴力猜测。

# 备选

- **谁先注册谁是站长**：部署到站长注册之间的窗口里，任何访问者都能抢到站长。
- **环境变量里的管理员口令**：静态秘密，难轮换，有弱口令风险；邀请码用一次就失效。
- **OAuth（GitHub、Google、微信）**：朋友不一定有 GitHub；Google 在中国大陆不可用；微信登录需要开放平台资质；每个提供方都要保管 client secret、配置回调域名。邀请加密码已经够用。
- **邮箱验证码或魔法链接**：需要发信服务，还要配置域名的 SPF、DKIM，国内邮箱的送达率也不稳定。
- **Cloudflare Access**：面向内部应用的门禁，要求访问者先登录；这里需要匿名浏览公开内容。
- **Passkey（WebAuthn）**：体验好，但要设计设备丢失后的恢复流程；留作后续增强，可以与密码并存。
- **JWT 无状态会话**：无法即时撤销（退出、封号），要靠密钥轮换；KV 会话直接删除即可。
- **会话放 D1**：需要定期清理过期行；KV 自带 TTL。
