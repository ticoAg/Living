# 用户故事

- 访客打开首页，看到大家最近公开的照片，点进任意一张。
- 用户只想看"秋天的湖"：选 秋 和 湖，结果立刻更新，别的标签里没有结果的自动变灰。
- 用户想在客厅播放刚筛出来的照片：点 Living。

# 规则

- 首页：所有用户的 `public` 照片；个人主页 `/@handle`：该用户可见的照片，本人还能看到 `unlisted` 和 `private`。
- 排序：默认按拍摄时间倒序；可切换"随机"（固定种子，刷新前顺序不变）。
- 筛选条件之间是"并且"。选中一个父标签等于选中它的所有子孙标签（见 [多层级标签](/product/features/hierarchical-tags.md)）。
- 城市来自照片的逆地理编码结果；没有结果的城市变灰不可选。
- 色调标签（带颜色的标签）显示为色块。
- 筛选状态写进地址栏（`?tags=lake,autumn&city=杭州`），可分享、可回退。
- 瀑布流保持原图比例，每张照片下方显示地点名和类别符号（一行，放不下时省略号）；没有公开地点时显示城市。
- 照片按顺序横着排：第一行是最新的几张，之后每张放进当时最矮的一列；Tab 和读屏器也按这个顺序（时间顺序）走。列数与宽度的关系：每列至少 150px，最多四列。
- 先显示 20 张，滚到离底部不远时再接上 20 张。从照片页返回时，已经接出来的照片都在，落回离开时的位置。照片页的上一张、下一张走的是完整的筛选结果。
- Living 按钮沿用当前筛选；没有任何筛选时随机播放全部（见 [Living 模式](/product/features/living-mode.md)）。

# 验收

- 1000 张照片时筛选响应在 100 ms 内（客户端过滤）。
- 手机宽度两列，桌面四列；首屏图片用 ThumbHash 占位，加载后淡入。
