# 流程

1. 拖入或选择多张照片（JPEG、PNG、WebP、AVIF、HEIC；单张不超过 50 MB）。iPhone 默认拍出的 HEIC 在所有浏览器里都能上传，见 [HEIC 与 HEIF](#heic-与-heif)。
2. 浏览器端逐张处理：读取 EXIF（时间、时区、GPS、海拔、朝向、相机、镜头、焦距、光圈、快门、ISO）；按方向旋正；生成长边 480 / 1600 / 2560 的 WebP（不支持时用 JPEG）；生成 ThumbHash；提取 5 个主色；计算 SHA-256 用于去重。生成的图不含 EXIF。
3. 有 GPS 的照片请求 [地点匹配](/product/features/poi-matching.md)，自动选中第一名；拿不准时标记"待确认"。
4. 没有 GPS 的照片，按拍摄时间找同批里前后 2 小时内最近的一张有地点的照片，给出"按时间推断"；也可以搜索地点或新建自定义地点。有 GPS 的照片可以在附近地点列表里选，或搜索附近的地点。搜索结果按 A、B、C 编号，同时标在地图上（有 GPS 时与候选一起，没有时单独出一张地图），点地图上的字母或列表都能选中，见 [地点匹配](/product/features/poi-matching.md#界面)。
5. 每张照片可填标题、[笔记](/product/features/photo-notes.md)、[标签](/product/features/hierarchical-tags.md#打标签)、公开范围、位置精度、加入哪些 [主题](/product/features/themes.md)。照片还在处理时就能填，只有发布要等处理完。标签不自动建议，全部由人选。是否进入 Living 和收藏不在上传时选：默认进入 Living、不收藏，发布后在照片编辑页修改。几张照片要同样的标签或设置时，在队列里多选，见 [一起整理](#一起整理)。
6. 发布：上传原图和三种尺寸到 R2，写入 D1。可逐张发布、发布所选，或 [全部发布](#全部发布)。

# 版面

- 还没有照片时：标题、说明和大的拖放区。
- 有照片后，标题和拖放区缩成一行（"添加照片"，整页仍可拖入），下面是三栏工作区：队列、照片与地点、整理。
- 宽度 1180 像素以上时，工作区正好占满窗口：页面本身不滚动，三栏各自滚动；发布按钮固定在右栏底部。窄一些的屏幕上恢复整页滚动，右栏的发布按钮跟在表单后面；多选时右栏（一起整理）排到照片前面。
- 左栏：队列标题、"同处 N 张"和"全选"一行；各状态的数量；"全部发布（N）"。每一行是缩略图、文件名、拍摄时间、状态，已匹配的照片状态处直接写地点名（颜色仍表示已匹配），有标签时再列出标签名。缩略图左上角是勾选框：用鼠标时悬停才出现、勾选了照片后一直显示，触屏上一直显示。
- 中栏：文件名和状态一行；预览限高（约三成窗口高度）；拍摄信息压成两行（时间、坐标、朝向、海拔；相机、曝光、尺寸，生成的三种尺寸在尺寸上悬停可见）；地点选择器：当前地点、地图、半径滑块与匹配状态一行、搜索一行、候选列表（先显示最近的 8 个）。
- 右栏：标签在左、控件在右的紧凑表单——标题、笔记（3 行）、标签、公开、位置、主题。勾选两张以上时换成 [一起整理](#一起整理) 面板。
- 用鼠标操作时，标签、输入框和分段按钮更矮（30–40 像素）；触屏上保持 44 像素。

# 一起整理

在队列里勾选两张以上，右栏换成"已选 N 张"：

- **怎么选**：点缩略图上的勾选框，勾的就是那一张；按住 Ctrl/⌘ 点一行，从当前显示的照片开始加减（和文件管理器一样）；按住 Shift 点一行，选中从上次点的那张到这张之间的所有照片；"全选"选中所有还能修改的照片。单击一行（不按键）只显示那一张并取消勾选；Esc 或"取消选择"取消勾选。只勾一张时照常显示那一张的表单，勾选框保持显示，方便接着勾。
- **同一处的一组**：当前照片有 GPS、附近还有别的照片时，队列标题旁出现"同处 N 张"，点一下选中这一组（当前照片保持显示），再点一下取消。分组从当前照片出发：拍摄位置与组里任一张相距不到 200 米的照片并进来，再从它出发接着找，但离当前照片不超过 1 千米；只算有 GPS、还能修改的照片。
- **改什么**：地点、标签、公开范围、位置精度、主题。标题和笔记仍逐张填。所选照片的缩略图排在面板顶部，点一张就在中栏显示它，那里仍可以单独给它换地点。
- **三种状态**：所有照片都有的标签实心显示；只有部分照片有的虚线显示（搜索框里的标签和标签板上都是）。点虚线的标签就给所有照片加上；点实心的标签就从所有照片去掉；搜索框里标签的 × 从有它的照片上去掉。季节、光线、色调逐张互斥：给一批照片加"秋"，其中带"春"的变成"秋"。公开范围和位置精度不一致时，分段按钮都不按下；在隐私区域内的照片位置保持隐藏。主题同标签。
- **不改的**：已发布、发布中和读取失败的照片可以留在所选里，但不会被修改，缩略图变淡。

## 一起选地点

面板第一行是地点：所选照片都在同一个地点时显示它和张数（可"清除"），否则显示"N / M 张有地点"或"未选择地点"。

- **候选**：所选照片各自匹配结果的并集，出现在越多照片里的越靠前，一样多时按到这些照片的平均距离排；行上标出"N 张"。先显示 4 个，其余点"显示全部"。本次新建的地点排在最后。下面是搜索（以所选照片的中心为准，搜附近约 6 千米）和"新建地点"（建在所选照片的中心；都没有 GPS 时建在时间最近的照片的位置）。
- **套用**：点一个地点，立刻用于所选里所有还能修改的照片，下方说明结果，例如"「断桥」已用于 5 张；1 张离得太远，没有改。"还在处理的照片也不改。
- **太远**：照片离地点超过 500 米加该类地点默认半径的两倍时不套用：桥 620 米、店 560 米、景 740 米、园 900 米、山 1.3 千米、湖 1.7 千米（默认半径见 [地点匹配](/product/features/poi-matching.md#自动与确认)）。照片自己的匹配结果里有这个地点（在它的匹配半径内，或照片就在这个面状地点范围内）时不算太远；没有 GPS 的照片和没有坐标的地点也不算。
- **记为什么**：与逐张选择一致。从候选里点、而这张照片自己的匹配结果里也有这个地点的，记为"已确认"（`confirmed`），距离和朝向按这张照片自己的；这张照片的结果里没有它、或从搜索和新建来的，以及没有 GPS 的照片，记为"手动选择"（`manual`），距离按照片到地点的直线距离。
- **新地点只建一次**：新建的地点当场写入站点，所有照片指向同一个地点。自建地点没有来源编号，服务端不会去重，所以套用前若选中的地点还没有入库、又没有来源编号，先建好再套用，不会每张照片各建一个同名地点。高德和 OpenStreetMap 的地点按来源编号去重，发布时第一张建、其余沿用。
- **发布所选（N）**：把所选里还没发的照片照原样发布，规则同 [全部发布](#全部发布)；没发出去的（失败的）保持勾选。

# 全部发布

左栏的"全部发布（N）"一键把队列里所有还没发布的照片照原样发出，N 包括还在处理的照片：

- 不需要先修改：已匹配的带上地点，待确认和无位置的不关联地点（仍记录省市区县，有的话），位置不公开的照样隐藏位置。已经填的标题、笔记、标签、设置都会带上。
- 刚拖进来就能点：还在读取或匹配地点的照片，等它好了再发；没有 GPS 的照片等同批其他照片都匹配完再发，因为它的地点可能按拍摄时间从别的照片推断。
- 一张一张发，按钮上显示"发布中 3 / 12"，旁边可"停止"（正在发的那张会发完）。每张只试一次：失败的留在队列里，可以逐张重试或再点一次全部发布。期间手动发布的照片不会重复发。
- 结束后在顶部说明结果，例如"已发布 10 张，1 张以前传过，1 张失败，可以重试。"重复的文件（SHA-256 相同）照常标为"已存在"。

# HEIC 与 HEIF

iPhone 默认拍出 HEIC。Safari 能直接解码它，Chrome、Edge、Firefox 不能，所以上传页带了一个后备解码器：

- **何时启用**：浏览器自己解不开、而文件是 HEIC/HEIF（按扩展名、MIME 类型，或没有这两者时按文件头里的品牌判断）。这时用 [libheif](https://github.com/strukturag/libheif) 的 WebAssembly 构建（npm 包 `libheif-js`）解码成像素，之后和其他格式走同一条管线：旋正、三种尺寸、ThumbHash、主色、SHA-256。选型理由见 [决策：浏览器端处理图片](/architecture/decisions/0002-client-side-images.md)。
- **只在需要时加载**：解码器压缩后约 0.7 MB，放在单独的 Worker 文件里，主包和上传页的代码都不含它；选 JPEG、PNG 等不会下载它。一批照片里只加载一次，最后一张解码完 15 秒后释放（WebAssembly 的内存不会自己缩小）。
- **不卡页面**：解码在后台线程（Web Worker）里进行，12 MP 的照片约 1 秒，页面照常响应。状态仍是"处理中"，队列里那一行写着"加载 HEIC 解码器…"或"解码 HEIC…"，右侧面板有对应的说明。
- **EXIF**：由 `exifr` 直接从 HEIC 文件读取，时间、时区、GPS、海拔、朝向、相机、镜头、曝光参数与 JPEG 一致。相机直出的 `.hif`（文件头品牌是 `heix`）`exifr` 不认，照片可以上传，但读不到时间和位置。
- **方向**：HEIC 把旋转写在文件容器里（`irot`、`imir`），libheif 解码时已经应用，得到的像素本身就是正的，不会旋转两次；照片尺寸记的是旋正后的宽高。
- **颜色**：iPhone 的 HEIC 带 Display P3 色彩描述文件，而解码器给出的是没有色彩管理的 RGB 值。上传页读取文件里的描述文件（只读 `meta` 区），把像素标成 `display-p3`，由浏览器转成 sRGB，结果和 P3 的 JPEG 一样饱满。没有描述文件的（多数安卓手机）、sRGB 的，不做转换。
- **原图原样保存**：HEIC 不转码，存成 `.heic` 或 `.heif`（取决于浏览器报告的类型），只有所有者能读，见 [R2 媒体文件](/data/media.md)。查看者只会拿到 WebP/JPEG 尺寸图，任何浏览器都不需要解码 HEIC。
- **失败只影响那一张**：队列里其他照片照常处理，这一张标为"失败"，面板里用中文说明原因，可以重试。会失败的情形有：解码器加载失败（离线或被拦截）、文件被截断或已损坏（libheif 对残缺的文件不报错，只会补灰，所以解码前先检查文件结构是否完整）、像素超过 1 亿（解码时每个像素约占 20 字节，内存不够会让整个标签页崩溃，未发布的队列随之丢失）、内存不足、解码超过 3 分钟。

# 队列状态

已匹配 / 待确认 / 无位置 / 位置不公开（在隐私区域内）/ 已发布 / 已存在 / 失败（可重试）。处理中的照片显示"处理中"。已匹配的照片在队列行里直接显示地点名。

# 规则

- 单张原图上限 50 MB；同一用户重复上传同一文件（SHA-256 相同）时提示已存在并跳过。
- 原图原样保存（HEIC 也是），只有本人能下载；公开展示只用生成的尺寸。
- 上传中途关闭页面，未发布的照片不会入库。

# 编辑

`/studio/photo/:id` 可以修改标题、笔记、标签、地点、公开范围、位置精度、是否进入 Living、收藏，或删除照片（同时删除 R2 中的所有文件）。
