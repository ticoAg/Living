# 背景

Living 原来围绕照片：上传、地点匹配、标签、主题和游记都从照片出发。作者想记下的很多东西没有照片，或者照片只是其中一部分：一页练字、一章读书笔记、一段灵感、一次补录的旅行。把这些写进照片笔记或主题的文字段落都很勉强：没有照片就没有地方写，主题又是为编排和展示设计的。

方向见 [Issue #47](https://github.com/ticoAg/Living/issues/47)，产品上的边界见 [内容模型](/product/content-model.md)。

# 决定

- **记录是独立的表**：[entries](/data/entries.md) 有自己的发生时间、Markdown 正文、类型、状态和公开范围，可以只有文字。不把照片表扩成「什么都能存」，也不把照片笔记迁成记录。
- **照片是媒体，被引用而不是被拥有**：[entry_media](/data/entry-media.md) 带顺序和记录内的说明；照片的公开范围、标签、地点仍属于照片本身。删除记录不删照片，删除照片从记录里移除它。
- **状态与公开范围分开**：`status`（草稿、已完成、已归档）决定公开范围是否生效，他人只看到已完成的。这样改回草稿或归档时不必动公开范围，恢复后也不用重新设。
- **默认仅自己可见**：记录默认 `private`；照片上传默认值暂不改，理由见 [数据演进](/data/evolution.md#照片的默认可见性)。迁移不改变任何已有内容的公开范围。
- **一棵标签树，分开挂**：[entry_tags](/data/entry-tags.md) 与 `photo_tags` 共用标签，但互不影响。
- **发生时间是本地时间，可以只有日期**：与照片的 `taken_at` 一致，由浏览器给出；只有日期的记录排在当天最后。
- **乐观并发**：每次修改让 `revision` 加一，编辑器带着它保存，过期时 409，由作者选择保留哪一份，不静默覆盖。
- **Markdown 自己解析**：只支持一个子集，渲染为 React 元素，不生成 HTML、不加载外部图片，链接只允许 http(s)、mailto 和站内地址。
- **导航按身份分开**：访客照旧看到图库、主题、地图、索引；登录后是今天、档案、图库（照片、地图、索引合为一处）、主题，登录后默认来到「今天」。

# 后果

- 现有页面、接口和数据都不变，旧链接继续可用；主题、游记和 Living 照旧以照片为主。
- 照片删除、标签删除、个人主页和标签计数都要多照顾记录一张表，权限条件集中在 `worker/lib/visibility.ts`。
- 时间线在前端合并记录与照片，两个列表各有 5000 条的上限；超过时需要分页或按年份取，到时再改接口。
- 项目、合集（由主题演进）、全文搜索和导出留给后续阶段，见 [路线图](/product/roadmap.md)。

# 备选

- **在照片表上加「无图照片」**：改动最小，但照片的地点、EXIF、尺寸图和图库逻辑都要为「没有图」开例外，隐私规则也会更难推理。
- **把主题当作记录**：主题已有标题、导语和文字段落，但它为编排设计，一条随手记不应该先建一个主题。
- **引入 CMS 或外部笔记服务**：与私有自托管的目标不符，也会让照片和记录分在两个系统里。
- **用现成的 Markdown 库**：功能更全，但体积更大，要靠配置关掉 HTML 和图片；需要的子集不大，自己解析更容易保证安全边界。
