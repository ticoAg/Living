# 用户故事

- 站长换了一个新的 Living 站点：在新站点注册后，到设置的「导入」选之前 [导出](/product/features/export.md) 的文件夹，记录、照片、项目和合集都回来了，记录之间的链接也指向新站点。
- 不小心删掉了一个合集和里面的几条记录：导入上个月的导出，删掉的回来，其余已经在的原样跳过。
- 导到一半网断了：再导入一次，已经导入的照片和记录跳过，从没导完的地方接着做。

# 规则

- **入口**：[设置](/product/features/accounts.md) 的「导入」。选导出的文件夹（`living-ada/`，或者它所在的文件夹），或者导出的全部 zip（分成几个的要一起选）。电脑上两种都行，手机上选 zip。只选一份导出：选中的里面有两份时会提示。
- **读取**：先读 living.json，问这里已经有什么，列出导出里的记录、照片、项目、合集各有多少，其中多少已经在这里、会跳过，要上传多大。照片的文件不在选中的文件里时（zip 少选了一个）写明有几张；导出时没带原文件的照片只有信息，不会导入。点「开始导入」才开始写。
- **公开范围**：照导出里的。打开「全部设为私密」时，导入的照片、记录、项目和合集都是仅自己可见，之后再一个个公开。
- **顺序**：标签、地点和隐私区域，然后是照片，最后是项目、记录和合集。照片一次一两张：从原文件重新生成三种尺寸，和 [上传](/product/features/upload.md) 一样存原文件。
- **照片的信息**取自 living.json：标题、说明、拍摄时间、位置和它的公开方式、地点、相机参数、标签、公开范围、收藏、是否在 Living 里。不从原文件的 EXIF 重新读，在原站点去掉的位置不会因为原文件里还留着而回来。位置落在自己的 [隐私区域](/product/features/privacy.md#隐私区域) 里时照样隐藏。上传时间是导入的时间。
- **记录、项目、合集**：创建和修改时间照导出里的，草稿还是草稿，已归档的还是已归档；项目带着里程碑，合集带着日期分段、文字、照片和记录，顺序不变。
- **已经在这里的跳过，不覆盖**：
  - 照片按文件内容认（和上传时判断重复一样）。
  - 记录、项目、合集按编号认：导出自这个账号、之后没有删的，或者以前导入过的。
  - 标签按编号，或者同一个上级标签下的同名标签；地点按编号，或者地图服务里的同一个地点；隐私区域按名称、中心和半径。
  - 已经在这里的保持现在的样子，导出里的版本不会盖过它；这里有、导出里没有的也不动。
- **删掉后再导入**：回来的照片、记录、项目和合集换了新的地址；已经在这里的记录里指向它们旧地址的链接不会改。
- **链接**：正文、说明和合集文字里指向原站点上的记录、照片、项目、合集的链接，换成这个站点上的地址；写着它们编号的地方，也换成这里的编号。指向原站点其他页面的链接不变。
- **指向的东西没导入时**：记录里去掉那张照片，合集里去掉那一项，封面空着。
- **不导入的**：分享链接（导出里没有它们的地址，要的话重新分享）、个人资料和设置。
- **进度**：照片按字节算。可以随时取消；离开这一页也会停下，关标签页前浏览器会先问。停下时已经导入的留着，再导入一次接着做。
- **网络**：一次请求失败时等 1、4、15 秒再试，仍然失败才停下。登录失效时停下，重新登录后再导入一次；数据库当天的额度用完时停下，北京时间 8 点以后再导入一次。
- **没能导入的**：照片的文件读不出、格式认不出或超过 50 MB；记录、项目、合集不合要求（比如记录里的照片一张都没导入，成了空的）。结束时列出每一项和原因，其余照常导入。

# 隐私

- 只能导入到自己的账号，导入的东西都是自己的；拿着别人的导出也只是把那些内容存成自己的。
- 文件在浏览器里读，只有要上传的照片和 living.json 里的信息送到站点。原文件带着原来的 EXIF，和上传时一样存着，只有自己能下载原文件。
- 公开的内容导入后马上公开。不确定时打开「全部设为私密」。

# 额度

导入在浏览器里完成，每张照片一次上传请求，其余的每批一次请求，Worker 每次只处理一批，档案再大也不会超时。免费版的 D1 每天能写 10 万行，一张照片约写 10 行，所以一天大约能导入一万张照片；用完时导入停下，第二天再导入一次接着做。导入的照片占这个站点的 R2 存储（免费 10 GB），见 [费用](/architecture/cloudflare.md#费用)。
