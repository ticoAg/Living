# 背景

照片带着 GPS 和镜头朝向，但用户想要的是"断桥""孤山"这样的名字，而不是坐标。需要从某个数据源里找出拍摄点附近的候选，并选出最可能的那个。

约束：

- 主要用户在中国大陆，高德的 POI 覆盖和中文名称最好；OpenStreetMap 在国内覆盖稀疏，但免费、无需 Key。
- 高德使用 GCJ-02 坐标，而照片 GPS 是 WGS-84；数据库和接口统一用 WGS-84。
- 外部服务有配额和使用政策，Overpass 和 Nominatim 是公共实例，不能每张照片都实时请求。
- 没有高德 Key 的部署（例如别人 fork 的）也要能用。

# 决定

1. **候选来源**：站内 `pois`（所有用户共享，优先）；外部候选——配置了 `AMAP_KEY` 且坐标在中国大陆范围内用高德周边搜索，其余情况用 OpenStreetMap，经免费公共服务 Photon（komoot）查附近地点，Photon 不可用时退到 Overpass；城市和区县来自逆地理——高德 regeo 或 Nominatim。按名称搜索在有坐标时限定在照片周围约 6 千米。高德只覆盖中国大陆，所以境外照片即使有 Key 也走 OpenStreetMap。
2. **坐标系**：库内和接口一律 WGS-84。调用高德前用 `wgs84ToGcj02` 转换查询点，结果用 `gcj02ToWgs84` 转回。两个函数和范围判断 `outOfChina` 都在 `shared/geo.ts`。
3. **排序**：分数 = 距离（米）− 25（候选在镜头朝向 ±30° 内）− 10（站内已有地点），越小越靠前。面状地点（湖、公园、区县）在其范围内时距离记为 0，排在点状地点之后作为兜底。
   - 朝向扣分：GPS 有误差，拍摄对象又常在几十米外；朝向能把身后的地点排到面前的后面。
   - 站内扣分：用户确认过的地点比外部原始数据更可信，也避免重复新建。
4. **自动与确认**：第一名距离不超过 25 米且在朝向内，或距离不超过 15 米，自动匹配；否则标为待确认，由用户选择。匹配半径默认 300 米，可调 30–1000 米。详见 [地点匹配](/product/features/poi-matching.md)。
5. **缓存与降级**：外部结果和逆地理放 KV 7 天，键里带数据源和坐标网格，见 [KV](/data/kv.md)。外部请求超时 8 秒；失败时只返回站内候选，`provider` 为 `local`。
6. **按需落库**：只有用户选中的外部候选才写入 `pois`，按 `(source, source_id)` 去重，并保留 `source` 以便回溯来源，见 [pois](/data/pois.md)。

# 后果

- 有 Key 时国内匹配质量明显更好；没有 Key 时也能用，但国内 POI 稀疏，更多照片需要手动搜索或新建地点。
- 缓存键含数据源，换数据源不会读到另一个源的缓存。
- 外部服务不可用不会阻塞上传：站内候选照常返回。
- 公共的 Overpass 实例经常过载：上线后从 Workers 发出的请求全部超时，所以 2026-11-08 起附近地点改由 Photon 提供，Overpass 只作后备。Photon、Nominatim 都是公益服务，有合理使用要求，Nominatim 还要求带有效的 User-Agent。缓存键把相近位置合并到约 10 米网格，批量上传同一景点的照片只会请求一次。
- 站内地点全站共享：别人建的地点你也能匹配到，越用越准；代价是 `pois` 没有可见性字段，所有登录用户都能搜到，见 [pois 的隐私说明](/data/pois.md#隐私)。
- 打分里的 25 和 10 是经验值，需要时再调整。
- 高德 Key 属于部署配置，不进仓库，见 [密钥与初始化](/runbooks/secrets.md)。

# 备选

- **只用站内地点（用户自建）**：零依赖，但每张照片都要手动命名，冷启动体验差。
- **Google Places、Mapbox、Foursquare**：国内覆盖或可用性差，或按量收费较高。
- **百度地图**（BD-09 坐标系，要另写一套转换）、**腾讯地图**：能力相近；高德的 Web 服务文档完整，个人开发者有免费额度。
- **只用 OpenStreetMap**：无需 Key，但国内中文地点缺得多；保留为无 Key 时的兜底。
- **把离线 POI 数据集（OSM 导出或 Overture）放进 D1**：体积大、更新麻烦，D1 免费版单库只有 500 MB。
