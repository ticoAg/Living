# 用户故事

- 访客打开首页，看到大家最近公开的照片，点进任意一张。
- 用户只想看"秋天的湖"：选 秋 和 湖，结果立刻更新，别的标签里没有结果的自动变灰。
- 用户想在客厅播放刚筛出来的照片：点 Living。
- 访客想看大家写了什么：切到「记录」，只看「练习」，再点 Living 放这些练习里的照片。

# 规则

- 首页：所有用户的 `public` 照片；个人主页 `/@handle`：该用户可见的照片，本人还能看到 `unlisted` 和 `private`。
- 访客的导航是图库、合集、地图、索引；登录后导航是今天、档案、图库、合集，图库、地图、索引和 [媒体库](/product/features/library.md) 合为「图库」一处，页面顶部用「照片 / 地图 / 索引 / 媒体库」切换。
- 排序：默认按拍摄时间倒序；可切换"随机"（固定种子，刷新前顺序不变）。
- 筛选条件之间是"并且"。选中一个父标签等于选中它的所有子孙标签（见 [多层级标签](/product/features/hierarchical-tags.md)）。
- 城市来自照片的逆地理编码结果；没有结果的城市变灰不可选。
- 色调标签（带颜色的标签）显示为色块。
- 筛选状态写进地址栏（`?tags=lake,autumn&city=杭州`），可分享、可回退。
- 瀑布流保持原图比例，照片是 8px 圆角，鼠标悬停时照片略微放大；每张照片下方显示地点名和类别符号（一行，放不下时省略号）；没有公开地点时显示城市。
- 标签筛选每个根一行：以分组开头的行（自然、光线）分组名加粗；直接是标签的行（春夏秋冬）行首写根的名字（季节）。
- 照片按顺序横着排：第一行是最新的几张，之后每张放进当时最矮的一列；Tab 和读屏器也按这个顺序（时间顺序）走。列数与宽度的关系：每列至少 150px，最多四列。
- 先显示 20 张，滚到离底部不远时再接上 20 张。从照片页返回时，已经接出来的照片都在，落回离开时的位置。照片页的上一张、下一张走的是完整的筛选结果。
- Living 按钮沿用当前筛选；没有任何筛选时随机播放全部（见 [Living 模式](/product/features/living-mode.md)）。
- 照片超过 5000 张时，接口只返回最新的 5000 张（见 [照片接口](/api/photos.md#get-apiphotos)），筛选栏下方显示一行「只显示最近的 5000 张」，手机上也不收进筛选里。
- 手机上标签筛选收起：照片上方一行是「筛选」按钮和 Living，按钮上显示已选标签的个数；点开后标签行在这一行下面展开，把照片往下推，不遮住照片。

# 记录

首页筛选栏最前面的「照片 | 记录」切换两层，记录这一层记作 `?layer=entries`。个人主页没有这个切换：那里有作品和文章（[作品与文章](/product/features/showcase.md)）。

- 所有人已完成的公开记录（[记录接口](/api/entries.md#get-apientries) 不带参数），按发生时间倒序，和作品一样排成格子：每条是它的第一张照片；没有照片时是视频的封面，再没有就是正文开头；下面是名字和日期。点开是记录。
- 封面的照片按 id 要，每 48 条一次。照片里只有看的人能打开的才算（仅自己可见的照片不当别人的封面）；一张也没有的记录照常列出，用视频的封面或正文开头。
- 先显示 48 条，「显示更多」再接 48 条。超过 5000 条时只列最近的 5000 条，写一行「只显示最近的 5000 条」。
- 类型筛选只列这一层有的类型，一次一个，记作 `?type=practice`；再点一下取消。没有符合的记录时给「清除筛选」。
- Living 放这些记录里的照片，沿用类型（`/living?src=entries&type=practice`，见 [Living 模式](/product/features/living-mode.md#记录)）；一张照片也没有时按不了。
- 切换时只保留这一层的筛选：去记录丢掉标签和城市，回照片丢掉类型。

# 验收

- 1000 张照片时筛选响应在 100 ms 内（客户端过滤）。
- 手机宽度两列，桌面四列；首屏图片用 ThumbHash 占位，加载后淡入。
